---
title: "Sincronizar cuentas de una cartera"
description: "Sincroniza por lotes filas de cuentas en una cartera con los modos APPEND_ONLY, UPDATE_EXISTING y REPLACE, e informa por qué salen las cuentas."
---

Carga y mantén las cuentas de deuda de una cartera desde tu propio sistema de origen con
`client.portfolios.syncAccounts`. Envías un lote de filas de cuentas y un modo de fusión;
QCobro empareja cada fila con una cuenta existente por su `externalId` y aplica el modo que
elegiste.

## Requisitos previos

<Note>
  `syncAccounts` está acotado a un workspace. Necesitas un [`Client`](/sdk/authentication)
  autenticado con un workspace activo seleccionado, y el `id` de una cartera donde sincronizar. Crea
  una antes con [`client.portfolios.create`](/sdk/portfolios).
</Note>

## Sincroniza un lote

<Steps>
  <Step title="Autentícate y selecciona un workspace">
    Construye un cliente, inicia sesión y elige el workspace al que pertenece la cartera.

    ```ts
    import { Client } from "@qcobro/sdk";

    const client = new Client();
    await client.login({ email: "me@acme.com", password: process.env.QCOBRO_PASSWORD! });
    client.useWorkspace("WO6ueex0qan9ojhf820wgiae3qi5luy08y");
    ```

  </Step>
  <Step title="Envía las filas">
    Pasa el `portfolioId`, un `mode` y al menos una fila o una salida (solo `REPLACE` acepta
    un lote vacío). Cada fila necesita un `externalId`, un `fullName` y un
    `outstandingBalance`.

    ```ts
    const result = await client.portfolios.syncAccounts({
      portfolioId: "f47ac10b-...",
      mode: "APPEND_ONLY",
      rows: [
        { externalId: "A-1", fullName: "Jane Doe", outstandingBalance: 1200.5 },
        { externalId: "A-2", fullName: "John Roe", outstandingBalance: 845 }
      ]
    });
    ```

  </Step>
  <Step title="Lee los conteos">
    La llamada devuelve cuántas cuentas se crearon, actualizaron y archivaron, el nuevo total
    activo de la cartera, las salidas por motivo y las recuperaciones detectadas.

    ```ts
    console.log(result);
    // {
    //   created: 2, updated: 0, archived: 0, total: 2,
    //   exitsByReason: { CAUGHT_UP: 0, PAID_OFF: 0, WRITTEN_OFF: 0, OTHER: 0, UNKNOWN: 0, classified: 0, skipped: 0 },
    //   recoveries: { partial: 0, caughtUp: 0, paidOff: 0, amount: 0 }
    // }
    ```

  </Step>
</Steps>

## Elige un modo de sincronización

El `mode` decide qué pasa con las cuentas existentes. Las filas se emparejan con las cuentas
por `externalId` dentro de la cartera.

| Modo              | Fila con un `externalId` nuevo | Fila que coincide con una cuenta existente | Cuenta existente **ausente** del lote |
| ----------------- | ------------------------------ | ------------------------------------------ | ------------------------------------- |
| `APPEND_ONLY`     | Se crea                        | Se deja sin cambios                        | Se deja sin cambios                   |
| `UPDATE_EXISTING` | Se crea                        | Se actualiza                               | Se deja sin cambios                   |
| `REPLACE`         | Se crea                        | Se actualiza                               | Se archiva como salida sin motivo     |

<Tabs>
  <Tab title="APPEND_ONLY">
    Añade cuentas nuevas y nunca toca las que ya existen. Úsalo para cargas incrementales en
    las que los datos previos son la fuente autoritativa.

    ```ts
    await client.portfolios.syncAccounts({ portfolioId: "f47ac10b-...", mode: "APPEND_ONLY", rows });
    ```

  </Tab>
  <Tab title="UPDATE_EXISTING">
    Añade cuentas nuevas y refresca las que ya existen: un upsert. Úsalo para feeds
    recurrentes que traen saldos o datos de contacto actualizados.

    ```ts
    await client.portfolios.syncAccounts({ portfolioId: "f47ac10b-...", mode: "UPDATE_EXISTING", rows });
    ```

  </Tab>
  <Tab title="REPLACE">
    Haz que la cartera refleje el lote: crea, actualiza y archiva cualquier cuenta cuyo
    `externalId` no esté en `rows`. Úsalo cuando el lote es una instantánea completa de la
    cartera. Un lote vacío (`rows: []`) es una instantánea válida: vacía la cartera archivando
    todas sus cuentas.

    ```ts
    await client.portfolios.syncAccounts({ portfolioId: "f47ac10b-...", mode: "REPLACE", rows });
    ```

  </Tab>
</Tabs>

<Warning>
  `REPLACE` **archiva** toda cuenta activa cuyo `externalId` no esté ni en `rows` ni en `exits`,
  como una salida **sin motivo**, y expira sus promesas de pago pendientes. Puedes darle el motivo
  más tarde, enviando la cuenta en `exits` en otra sincronización. Envía siempre una instantánea
  completa con `REPLACE`: un lote parcial archivará las cuentas que dejaste fuera.
</Warning>

## Informa las salidas

Una cuenta que se pone al día suele desaparecer de tu exportación de cuentas en mora. Eso es lo
esperado, pero QCobro solo la cuenta como recuperada si le dices por qué salió. Envía esas
cuentas en `exits`, en cualquier modo, junto a `rows` o solas.

```ts
await client.portfolios.syncAccounts({
  portfolioId: "f47ac10b-...",
  mode: "UPDATE_EXISTING",
  rows: [],
  exits: [
    { externalId: "A-1", reason: "CAUGHT_UP", missedInstallments: 3, termsAmount: 1500 },
    { externalId: "A-2", reason: "WRITTEN_OFF" }
  ]
});
```

<ParamField body="exits" type="array" default="[]">
  Cuentas que salen de la cartera, cada una con su `externalId` y su `reason`. La cuenta se archiva.
  Un `externalId` no puede estar a la vez en `rows` y en `exits`, ni repetirse en `exits`, y debe
  existir en la cartera.
</ParamField>

| `reason`      | Significado    | Campos adicionales                                        | Registra una recuperación                 |
| ------------- | -------------- | --------------------------------------------------------- | ----------------------------------------- |
| `CAUGHT_UP`   | Se puso al día | `missedInstallments` y `termsAmount`, ambos mayores que 0 | Sí, de `missedInstallments × termsAmount` |
| `PAID_OFF`    | Saldó la deuda | `missedInstallments` y `termsAmount`, ambos mayores que 0 | Sí, de `missedInstallments × termsAmount` |
| `WRITTEN_OFF` | Castigada      | Ninguno                                                   | No                                        |
| `OTHER`       | Otro motivo    | Ninguno                                                   | No                                        |

En `CAUGHT_UP` y `PAID_OFF`, `missedInstallments` son las cuotas que estaban vencidas y ahora están
pagadas, y `termsAmount` es el importe de cada cuota. Las promesas de pago pendientes de la
cuenta pasan a **Cumplida**.

Si la cuenta ya había salido sin motivo, la salida recibe el motivo que envías y la recuperación
cuenta en la fecha en que salió, así que la cifra de un período ya cerrado puede subir. Las
promesas que esa salida había expirado pasan a **Cumplida**. Enviar de nuevo una salida que ya
tiene motivo no cambia nada (`exitsByReason.skipped`), así que puedes reintentar una
sincronización sin duplicar nada.

## Cómo se detectan los pagos parciales

En `UPDATE_EXISTING` y `REPLACE`, si una cuenta sigue en el lote con menos `missedInstallments`
que en la sincronización anterior, QCobro registra un pago parcial: las cuotas que bajaron por el
`termsAmount` que tenía guardado la cuenta. Un aumento no registra nada. `APPEND_ONLY` no compara,
porque no actualiza las cuentas existentes.

Con cada recuperación y cada salida, QCobro guarda qué gestiones tuvo la cuenta entre la
sincronización anterior y esta: canal, resultado, campañas y días desde la última gestión. Ese
registro no se recalcula después.

## Da forma a las filas de cuenta

Cada entrada de `rows` se valida contra el esquema de cuenta compartido. Solo tres campos son
obligatorios; el resto es opcional, y los campos numéricos de abajo toman `0` por defecto
cuando se omiten. La excepción son `termsAmount` y `missedInstallments`: si los omites al
actualizar una cuenta, se conserva el valor guardado (y no se detecta ningún pago parcial).

<ParamField body="externalId" type="string" required>
  Tu identificador estable de la cuenta. Las cuentas se emparejan entre sincronizaciones por este
  valor, así que debe ser único dentro de la cartera.
</ParamField>
<ParamField body="fullName" type="string" required>
  Nombre completo del titular de la cuenta.
</ParamField>
<ParamField body="outstandingBalance" type="number" required>
  Importe adeudado actual. Debe ser cero o mayor.
</ParamField>
<ParamField body="phone" type="string">
  Teléfono de contacto usado para gestiones por voz y SMS.
</ParamField>
<ParamField body="email" type="string">
  Email de contacto. Debe ser una dirección válida cuando se aporta.
</ParamField>
<ParamField body="preferredLanguage" type="string">
  Idioma preferido para las gestiones (QCobro es multilingüe).
</ParamField>
<ParamField body="bestTimeToCall" type="string">
  Nota libre sobre cuándo prefiere ser contactado el titular.
</ParamField>
<ParamField body="customerSegment" type="string">
  Tu propia etiqueta de segmentación de la cuenta.
</ParamField>
<ParamField body="principalAmount" type="number" default="0">
  Principal original adeudado.
</ParamField>
<ParamField body="termsAmount" type="number">
  Importe de la cuota según las condiciones de la cuenta. `0` en una cuenta nueva si se omite; en
  una existente, se conserva el valor guardado.
</ParamField>
<ParamField body="termsFrequency" type="string">
  Cada cuánto vencen las cuotas (por ejemplo `monthly`).
</ParamField>
<ParamField body="termsLength" type="number" default="0">
  Número de cuotas del plazo.
</ParamField>
<ParamField body="daysPastDue" type="number" default="0">
  Días de mora de la cuenta.
</ParamField>
<ParamField body="missedInstallments" type="number">
  Número de cuotas impagadas. `0` en una cuenta nueva si se omite; en una existente, se conserva el
  valor guardado. Una bajada entre sincronizaciones registra un pago parcial.
</ParamField>
<ParamField body="lastPaymentDate" type="string">
  Fecha del último pago, como cadena de fecha ISO.
</ParamField>
<ParamField body="lastPaymentAmount" type="number">
  Importe del último pago.
</ParamField>
<ParamField body="negotiationOptions" type="string">
  Notas sobre opciones de negociación o acuerdo aceptables para esta cuenta.
</ParamField>

## Lee el resultado

`syncAccounts` resuelve a un resumen de lo que cambió:

<ResponseField name="created" type="number">
  Cuentas insertadas porque su `externalId` era nuevo para la cartera.
</ResponseField>
<ResponseField name="updated" type="number">
  Cuentas existentes refrescadas. Siempre `0` en `APPEND_ONLY`.
</ResponseField>
<ResponseField name="archived" type="number">
  Cuentas archivadas por esta llamada: las de `exits` en cualquier modo, y en `REPLACE` las ausentes
  del lote.
</ResponseField>
<ResponseField name="total" type="number">
  Número de cuentas activas de la cartera tras la sincronización (las archivadas se excluyen).
</ResponseField>
<ResponseField name="exitsByReason" type="object">
  Salidas creadas por esta llamada, por motivo: `CAUGHT_UP`, `PAID_OFF`, `WRITTEN_OFF`, `OTHER` y
  `UNKNOWN` (sin motivo). `classified` cuenta las salidas sin motivo que esta llamada clasificó (no
  se suman a los motivos) y `skipped` las entradas de `exits` que no cambiaron nada.
</ResponseField>
<ResponseField name="recoveries" type="object">
  Recuperaciones registradas por esta llamada: `partial`, `caughtUp`, `paidOff`, y `amount`, la suma
  de sus importes.
</ResponseField>

## Maneja los errores de validación

Las filas se validan **en el cliente** contra el esquema compartido de QCobro antes de enviar
cualquier petición. Estos casos lanzan un `ValidationError` con detalle por campo y no hacen
ninguna llamada de red:

- un lote sin filas ni salidas en `APPEND_ONLY` o `UPDATE_EXISTING`: `rows and exits must not both be empty in APPEND_ONLY mode (only REPLACE accepts an empty batch)`;
- un `mode` desconocido o un `email` malformado;
- un `externalId` en `rows` y en `exits`: `externalId "A-1" appears in both rows and exits`;
- un `externalId` repetido en `exits`: `externalId "A-1" appears twice in exits`;
- un `reason` desconocido: `reason must be one of CAUGHT_UP, PAID_OFF, WRITTEN_OFF, OTHER`;
- una salida `CAUGHT_UP` o `PAID_OFF` sin `missedInstallments` o `termsAmount` (`required when reason is CAUGHT_UP or PAID_OFF`), o con valores de 0 o menos (`must be greater than 0`).

El servidor rechaza además, sin escribir nada, una salida cuyo `externalId` no existe en la
cartera (`externalId(s) not in this portfolio: A-9`).

```ts
import { ValidationError } from "@qcobro/sdk";

try {
  await client.portfolios.syncAccounts({
    portfolioId: "f47ac10b-...",
    mode: "APPEND_ONLY",
    rows: [] // un lote sin filas ni salidas se rechaza fuera de REPLACE
  });
} catch (err) {
  if (err instanceof ValidationError) {
    console.error(err.fieldErrors); // [{ field: "rows", message: "...", code: "..." }]
  }
}
```

Consulta [Validación y errores](/sdk/errors) para la forma completa del error.
