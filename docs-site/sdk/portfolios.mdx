---
title: "Gestionar carteras"
description: "Lista, obtén, crea, actualiza, archiva y elimina carteras, lista sus cuentas y clasifica sus salidas con client.portfolios."
---

Una **cartera** agrupa las cuentas de deuda que QCobro gestiona para un cliente. El recurso
`client.portfolios` expone las operaciones sobre carteras como métodos tipados.

Todos los métodos están **acotados al workspace activo**: necesitas un `Client` autenticado
con un workspace seleccionado. Las entradas se validan en el cliente contra los esquemas
compartidos de `@qcobro/common` **antes** de enviar la petición: una entrada inválida lanza un
`ValidationError` y nunca llega a la red.

## Lista las carteras

`list` devuelve las carteras del workspace activo. Por defecto omite las archivadas; pasa
`includeArchived: true` para incluirlas.

```ts
const portfolios = await client.portfolios.list();

// Incluye también las archivadas.
const all = await client.portfolios.list({ includeArchived: true });
```

## Obtén una cartera

`get` devuelve una sola cartera por su `id` dentro del workspace activo.

```ts
const portfolio = await client.portfolios.get({ id: "f47ac10b-..." });
```

## Crea una cartera

`create` necesita un `name` y un `clientId` (tu identificador del cliente al que pertenece la
cartera).

```ts
const portfolio = await client.portfolios.create({
  name: "Morosidad Q3",
  clientId: "acme"
});
```

<ParamField body="name" type="string" required>
  Nombre visible de la cartera (1–120 caracteres).
</ParamField>
<ParamField body="clientId" type="string" required>
  Tu identificador del cliente al que pertenece la cartera (1–120 caracteres).
</ParamField>

## Actualiza o archiva una cartera

`update` cambia el nombre de una cartera o alterna su estado de archivado. Pon
`archived: true` para archivarla y `archived: false` para restaurarla.

```ts
// Renombra una cartera.
await client.portfolios.update({ id: "f47ac10b-...", name: "Morosidad Q4" });

// Archívala.
await client.portfolios.update({ id: "f47ac10b-...", archived: true });

// Restáurala.
await client.portfolios.update({ id: "f47ac10b-...", archived: false });
```

<ParamField body="id" type="string" required>
  Id de la cartera a actualizar.
</ParamField>
<ParamField body="name" type="string">
  Nuevo nombre (1–120 caracteres).
</ParamField>
<ParamField body="archived" type="boolean">
  `true` archiva la cartera; `false` la restaura.
</ParamField>

## Elimina una cartera

`delete` elimina una cartera del workspace activo.

```ts
await client.portfolios.delete({ id: "f47ac10b-..." });
```

<Tip>
  Para retirar una cartera de la vista operativa conservando su historial, prefiere
  **archivarla** (`update` con `archived: true`) en lugar de eliminarla.
</Tip>

## Lista las cuentas de una cartera

`listAccounts` devuelve una página de las cuentas de una cartera junto con el total. Acota la
página con `limit` (1–200) y `offset`.

```ts
const { accounts, total } = await client.portfolios.listAccounts({
  portfolioId: "f47ac10b-...",
  limit: 50,
  offset: 0
});
```

<ParamField body="portfolioId" type="string" required>
  Id de la cartera cuyas cuentas listar.
</ParamField>
<ParamField body="limit" type="number">
  Número máximo de cuentas a devolver (1–200).
</ParamField>
<ParamField body="offset" type="number">
  Número de cuentas a omitir desde el inicio (para paginar).
</ParamField>

## Lista las salidas de una cartera

`listExits` devuelve una página de las cuentas que salieron de una cartera y no han vuelto,
de la más reciente a la más antigua, junto con el total. Filtra por `reason`; por ejemplo,
`UNKNOWN` lista las salidas que aún esperan un motivo.

```ts
const { items, total } = await client.portfolios.listExits({
  portfolioId: "f47ac10b-...",
  reason: "UNKNOWN",
  limit: 50
});
```

<ParamField body="portfolioId" type="string" required>
  Id de la cartera cuyas salidas listar.
</ParamField>
<ParamField body="reason" type="string">
  Solo las salidas con este motivo: `CURED`, `PAID_OFF`, `WRITTEN_OFF`, `OTHER` o `UNKNOWN`
  (sin motivo).
</ParamField>
<ParamField body="limit" type="number" default="50">
  Número máximo de salidas a devolver (1–200).
</ParamField>
<ParamField body="offset" type="number" default="0">
  Número de salidas a omitir desde el inicio (para paginar).
</ParamField>

Cada elemento de `items` describe una salida:

<ResponseField name="id" type="string">
  Id de la salida.
</ResponseField>
<ResponseField name="externalId" type="string">
  Tu identificador de la cuenta.
</ResponseField>
<ResponseField name="fullName" type="string">
  Nombre completo del titular.
</ResponseField>
<ResponseField name="reason" type="string">
  Motivo de la salida, o `UNKNOWN` si salió sin motivo.
</ResponseField>
<ResponseField name="exitedAt" type="string">
  Cuándo salió la cuenta (ISO 8601).
</ResponseField>
<ResponseField name="missedInstallments" type="number">
  Cuotas vencidas guardadas en la salida: las de la cuenta al salir, o las que enviaste al darle
  motivo `CURED` o `PAID_OFF`.
</ResponseField>
<ResponseField name="termsAmount" type="number">
  Importe de cada cuota guardado en la salida, con el mismo criterio.
</ResponseField>
<ResponseField name="amountIfRecovered" type="number">
  `missedInstallments × termsAmount`. En una salida `UNKNOWN` es una estimación de lo que se
  registraría si la clasificas como `CURED` o `PAID_OFF`.
</ResponseField>
<ResponseField name="classifiedAt" type="string | null">
  Cuándo se dio el motivo a una salida que había salido sin él, o `null`.
</ResponseField>

## Clasifica las salidas sin motivo

Una cuenta que desaparece de un lote `REPLACE` sale **sin motivo** (`UNKNOWN`). `classifyExits`
le da el motivo después, sin tener que esperar a la siguiente sincronización. Las entradas
siguen las mismas reglas que `exits` en [Sincronizar cuentas](/sdk/sync-accounts#informa-las-salidas):
`CURED` y `PAID_OFF` llevan `missedInstallments` (las cuotas vencidas que ahora están pagadas)
y `termsAmount` (el importe de cada cuota), y registran una recuperación de su producto.

```ts
const result = await client.portfolios.classifyExits({
  portfolioId: "f47ac10b-...",
  exits: [
    { externalId: "C-0877", reason: "CURED", missedInstallments: 2, termsAmount: 1500 },
    { externalId: "C-0878", reason: "WRITTEN_OFF" }
  ]
});
// → { classified: 2, recoveries: { cured: 1, paidOff: 0, amount: 3000 }, promisesMet: 1 }
```

<ParamField body="portfolioId" type="string" required>
  Id de la cartera.
</ParamField>
<ParamField body="exits" type="array" required>
  Entre 1 y 1000 salidas, cada una con su `externalId` y su `reason` (`CURED`, `PAID_OFF`,
  `WRITTEN_OFF` u `OTHER`). Un `externalId` no puede repetirse.
</ParamField>

La llamada es de todo o nada: si una entrada no corresponde a una salida que espera motivo, no
se clasifica ninguna y la API responde con el error. La recuperación cuenta en la fecha en que
la cuenta salió, así que la cifra de un período ya cerrado puede subir. En `CURED` y `PAID_OFF`,
las promesas de pago que esa salida había expirado pasan a **Cumplida**.

<ResponseField name="classified" type="number">
  Salidas que recibieron su motivo.
</ResponseField>
<ResponseField name="recoveries" type="object">
  Recuperaciones registradas: `cured`, `paidOff`, y `amount`, la suma de sus importes.
</ResponseField>
<ResponseField name="promisesMet" type="number">
  Promesas de pago que pasaron a **Cumplida**.
</ResponseField>
